# Conventions

Decided once, used everywhere.

These are the conventions of the code as built. The town and its causal objects are described in [Architecture](ARCHITECTURE.md).

| Item | Rule | Why / check |
|---|---|---|
| Length | metres | |
| Angles | radians in code; degrees in data files (config), converted on load and marked `UNITS` | `[camera] fov_deg`, `Projection.h` |
| Coordinate system | **left-handed, +Y up, +X right, +Z forward** | DirectXMath `...LH` functions |
| Matrices | DirectXMath row-major, **row vectors**: `v' = v * M`; order `World * View * Projection` | `Models::DrawObjects`, `TownSession::Render` |
| HLSL | `#pragma pack_matrix(row_major)` (`common.hlsli`) **and** the compile flag `D3DCOMPILE_PACK_MATRIX_ROW_MAJOR`; `mul(v, M)`; **no CPU-side transpose** | `shaders/common.hlsli`, `render/ShaderCompiler.cpp` |
| Winding | clockwise = front face (Direct3D default) | `Models::CreateStates` (`FrontCounterClockwise = FALSE`), `tests/test_mesh.cpp` |
| UV | none yet: a mesh vertex is a position and a normal. When added: origin top-left (Direct3D) | `MeshData.h` |
| Colour | textures loaded as sRGB; lighting in linear space; the back buffer is written through an sRGB view (`R8G8B8A8_UNORM_SRGB` on a `R8G8B8A8_UNORM` flip-model swap chain) | `Device::CreateBackBufferView`; every colour in `config` is linear |
| Depth | **D32_FLOAT, compare LESS, cleared to 1.0 (far)** (`Device::BeginFrame`, `Models::CreateStates`, and the depth of the two ripple pictures; each texture is `R32_TYPELESS` with a `D32_FLOAT` depth view and an `R32_FLOAT` shader view, so that the ink lines and the rain can read it). Reverse-Z was considered and **not adopted** (decided 2026-11-18): the scene is small, and it would change four places. Revisit it only if far objects flicker | the models: a sphere in front of the floor hides it, behind it does not |
| Mesh vertex | position (3 floats) + normal (3 floats) = 24 bytes, no UV yet; indices are 32 bit | `MeshData.h` static_assert, input layout in `Models.cpp` |
| Mesh winding | clockwise seen from OUTSIDE; the outward normal is `cross(v1 - v0, v2 - v0)` (component formula); every shape is centred on its own origin, 1 m big | `tests/test_mesh.cpp`, every triangle of every shape |
| Normals | moved with the inverse transpose of the world matrix, not with the world matrix | `Models::DrawObjects`, `ObjectConstants.normalMatrix` |
| Layers | a layer is a label on an object, not a place in the world: a bit mask, **A = 1, B = 2, both = 3** (`SceneObject.layerMask`); a layer is numbered 0 (A) or 1 (B) in code | `kLayerA`, `kLayerB`, `kLayerBoth` in `scene/SceneData.h`, the `Tab` key |
| Layer look | each layer has its own theme (background and fog colour, fog density, light colour, light direction, sky colour, the tint and the weathering of the city); a layer is always drawn with ITS theme, themes are never mixed. A is the past, the whole city (warm, clear); B the present, the city after the storm (cold, foggy, mossy). Only the city takes the tint and the weathering: an object of both layers that does not glow (`color.a` = 1 in the model shader) | `[layer_a]`, `[layer_b]` in `config/default.ini`, `DefaultThemes` in `render/Models.cpp` |
| Layer pictures | during a ripple each layer is drawn complete into its own picture: colour `R8G8B8A8_UNORM_SRGB` (writing converts linear to sRGB, sampling converts back) and its own `D32_FLOAT` depth, the size of the back buffer; the ripple shader only chooses between the two pictures | `Models::DrawRipple`, `shaders/ripple.hlsl` |
| Objects | what is drawn one by one (the lantern, the things, the avatar, the sea, the guidance) is a `scene::SceneObject`: shape, place, scale, tilt, yaw, colour, moment mask. A shape is 1 m big before the scale. World matrix = Scale * RotationX(tilt) * RotationY(yaw) * Translation (the yaw: a fixed turn, such as a house turned to its street). The town itself is not made of objects: it is polygons baked into a static batch | `scene/SceneData.h`, `Models::DrawObjects` |
| Collision body | the flying camera is a ball (centre = the camera, radius `[collision] radius`, default 0.35 m); it is pushed out of the solid of the moment, never the other way. A solid exists only in its moment; during a ripple the moment that is opening counts (`Models::CollisionLayer`) | `scene/Moments.h`, `tests/test_lantern.cpp` |
| Walking body | three balls of the collision radius at the feet, halfway and at the eye (`[player] eye_height`, default 1.55 m); the camera is the eye; the feet are the point on the ground. Walking is the default, `F` flies, collision off also flies | `scene/Player.h`, `tests/test_player.cpp` |
| Walking numbers | `[player]` gravity 30 m/s^2, jump height 2.0 m (reaches the top of the 1.8 m objects), walk speed 5.5 m/s, fall speed at most 40 m/s; coyote time 0.08 s, jump buffer 0.10 s; the ground counts as standable when its push points up by at least 0.6 of its length (about 53 degrees) | constants at the top of `Player.h`, `[player]` in `config/default.ini` |
| Walking steps | a frame is cut into steps that move the body by less than 0.7 of the radius, and a frame longer than 0.1 s counts as 0.1 s, so that nothing is jumped over (the floor is 0.2 m thick) | `Player::Update` |
| Glow | `SceneObject::glow`: a light of its own, added as albedo * glow in the model shader (`params.w`), the same in both layers; 0 for ordinary objects, about 0.3 for traces, about 1 for lamps, the lantern and the guidance | `shaders/models.hlsl`, `render/Models.cpp` |
| Light | all light is linear; a lamp's colour is its colour times its strength (1 lights a wall with the light of the sun; a street lamp is 18, 3.4 m up: 1.4 on the ground under it); a lamp reaches `range` (14 m for a street lamp) and falls with the inverse square times the window `saturate(1 - (d / r)^4)^2`; at most `kMaxLamps` (32) per moment | `shaders/lighting.hlsli`, `render/Lights.h`, `tests/test_lighting.cpp` |
| Shadow map | one `D32_FLOAT` texture of 2048 x 2048 (typeless, with a depth view and a shader view), drawn once per moment drawn; an orthographic left-handed box of radius 60 m and depth 320 m centred 21 m ahead of the camera and moved on the texel grid; the lookup is 3 x 3 taps of a hardware comparison, a depth bias of 3 texels and a normal offset of 1.5; the pass has no pixel shader and draws both sides | `render/ShadowMath.h`, `Models::DrawObjects`, `tests/test_lighting.cpp` |
| Shoulder | the back buffer is written through an sRGB view, so a colour above 1 would be cut off: the last step of every colour in the model shader is the exposure, then `SoftShoulder` (knee 0.78: nothing below it changes, above it a colour is bent toward 1 and keeps its hue) | `shaders/lighting.hlsli`, `tests/test_lighting.cpp` |
| Overlay | screen pixels, (0, 0) at the top left, +y down; colours sRGB with alpha, converted to linear when drawn; drawn last, no depth | `render/OverlayBatch.h`, `render/Overlay.cpp` |
| Static batch | the town is baked into world-space vertices (`BatchVertex`, 56 bytes: position, normal, linear colour with the city flag in alpha, the shader parameters), one mesh per moment (`TownData::BakeLayer`) and one for the still water (`BakeWater`); each polygon is a fan of triangles, drawn from both sides except terrain and water | `render/StaticBatch.h`, `scene/Town.h`, `tests/test_town.cpp`, `tests/test_batch.cpp` |
| Stairs and slopes | the walking body snaps down 0.35 m, so a stair is modelled as the ramp under its steps; a slope steeper than about 53 degrees is not stood on (roofs). Limits of the town: streets 24 degrees, ramps 27, stairs 32 | `Player::kGroundFacing`, `tools/layout/city_model.py check` |
| Water | the water of A is drawn in the water pass and is never solid for the body: feet under its surface (`TownData::Submerged`) sink the body for `kSinkSeconds`, then it comes back to the last place it stood still on. In B the water of A exists only inside the circle of the lantern | `scene/Town.h`, `scene/TownEffects.h` |
| Moving things | the causal rule: a thing opened in A also changes B, never the other way; the trace of the change shows in B for a moment | `scene/Things.h`, [Design, causal rule](DESIGN.md#33-the-causal-rule) |
| Places of return | a fall, the water or R comes back to the last place the body stood still on, out of the water, standing in both moments without the circle of the lantern | `TownSession::ReturnFromFall`, `Moments::Supports` |
| Ground | the town model gives the terrain as polygons (kind terrain), solid for the body in both moments and flat-shaded; there is no other ground | `scene/Town.h`, `tests/test_town.cpp` |
| Sea | one box per layer at the sea level of the town, round the eye in steps of 20 m, 720 m across (wider than the far plane), ending at `kSeaNorthEdge`; drawn as `kMatSea`; not solid | `town::AddSea` in `scene/TownEffects.h`, `tests/test_effects.cpp` |
| Water materials | the `checker` of a `SceneObject` says how it is drawn: 0 plain, 1 checkered floor, 2 still water, 3 running water, 4 the sea, 5 the wet band, 6 foam, 7 a halo (`scene::kMatWater` ..). From 2 to 6 it is drawn in the water pass, and its `glow` is how opaque it is, not a light; 7 is added to the picture after the water (a glow round a lamp, not lit, no shadow) and its `glow` is its strength | `scene/SceneData.h`, `shaders/models.hlsl` |
| Far plane | 300 m (`render/Projection.h`); the sea is sized by `town::kViewDistance`, which must not be smaller | `static_assert` in `app/TownSession.cpp` |
| near, far | never a name in code that `windows.h` sees: it defines `near` and `far` as empty macros (`scene/Guidance.h` had a variable `far` and did not compile for Windows) | `render/Projection.h` |
| Switch guard | a switch is refused when the body would overlap anything solid of the target moment (with the circle of the lantern) or be under its water; it is never pushed through: the ripple opens for 0.15 s and turns back, and the old moment stays solid meanwhile (`LayerGuard::Action::Refuse`). A blocked request during a ripple is dropped | `scene/LayerGuard.h`, `FitsInTown` in `app/TownSession.cpp`, `tests/test_layer_guard.cpp` |
| Rotation on a row vector | DirectXMath `RotationY(a)`: x' = x cos a + z sin a, z' = -x sin a + z cos a (+90 degrees turns +Z into +X). `RotationX(a)`: y' = y cos a - z sin a, z' = y sin a + z cos a (+90 degrees turns +Y into +Z). | `Models::DrawObjects` (`XMMatrixRotationX`, `XMMatrixRotationY`) |
| Right of a direction | in this left-handed space the right of a flat forward direction f is (f.z, 0, -f.x): forward +Z gives right +X | `Player::Update`, `tests/test_player.cpp` (strafing) |
| Ripple units | the circle is measured in screen HEIGHTS (so it is round on a wide screen); the centre is 0 .. 1 over the screen, (0, 0) = top left | `[ripple]` in `config/default.ini`, `FarthestCornerDistance` |
| windows.h | `min` and `max` are macros unless `NOMINMAX` is defined **before the first include that pulls in `windows.h`** (also through other headers; a header that includes `<d3d11_1.h>` before the headers that use `std::min` sets it itself, as `GpuTimer.h` does). Where this order is not certain, do not use `std::min` / `std::max`; `std::clamp` and a plain `?:` are safe | `Models::Update` (the first M2 build failed with C2589), `LayerRipple.h`, `Player.h`, `GpuTimer.h` (23 errors of C2589 on 2026-11-28) |
| Feature level | 11_0 minimum (11_1 used when present) | |
| File encoding | UTF-8, no BOM, LF line ends (`.gitattributes`, `.editorconfig`) | |
| Naming | types and functions `PascalCase`, variables `camelCase`, members `m_`, constants `kPascalCase`, `enum class` | `.clang-format` formats, it does not rename |
